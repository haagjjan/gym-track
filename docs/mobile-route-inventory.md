### What the proxy helpers do beyond forwarding

- **Client IP attribution (`apps/web/src/shared/bff-client-attribution.ts`)**: All four proxy helpers call `addBffClientAttribution(request, headers)`. It reads `process.env.BFF_CLIENT_IP_SECRET` (requires length >= 32) and extracts an IP from `cf-connecting-ip`, the last entry of `x-forwarded-for`, or `x-real-ip` (validated with `node:net` `isIP`). When both are present, it adds `x-gym-client-ip` and an HMAC-SHA256 signature in `x-gym-client-signature`. Fastify's `onRequest` hook in `apps/api/src/server.ts` rejects non-health/non-metrics requests with `403` `BFF_REQUIRED` when `extras.clientIpSecret` is configured and this signature is missing/invalid.
- **Request ID and structured error logging (`apps/web/src/shared/server-logging.ts`)**: All four proxy helpers call `createBffRequestContext`, `forwardBffRequestId`, `finalizeBffResponse`, and `logBffFailure`. They validate incoming `x-request-id` against `/^[A-Za-z0-9._-]{1,128}$/` or generate a UUID, forward `x-request-id` to Fastify, set `x-request-id` on the client response (including `502 API_UNAVAILABLE` responses), and log JSON errors to `console.error` on `5xx` or network failures.
- **`proxyWorkoutApiRequest` (`apps/web/src/features/workouts/workout-api-proxy.ts`)**: Forwards `accept` (defaults to `application/json`), `content-type`, `cookie`, and `request.nextUrl.search`; buffers request body as text for non-`GET`/`HEAD` requests (omitting empty bodies); buffers upstream response as text; forwards `content-type` and `content-disposition` response headers; returns `null` body for status `204`, `205`, or `304`.
- **`proxyAuthRequest` (`apps/web/src/features/auth/auth-api-proxy.ts`)**: Sets `accept: application/json`, forwards `content-type` and `cookie`; buffers request body as text for non-`GET`/`HEAD` requests; does not forward query string; forwards `content-type` and `set-cookie` response headers.
- **`proxyAnalyticsApiRequest` (`apps/web/src/features/analytics/analytics-api-proxy.ts`)**: Sets `accept: application/json`, forwards `cookie` and `request.nextUrl.search`; does not forward `content-type` or request body; forwards `content-type` response header.
- **`proxyPublicStatus` (`apps/web/src/features/status/public-status-proxy.ts`)**: Checks `origin` header and rejects any non-empty origin other than `https://status.gymtrack.ch` with `403 CORS_NOT_ALLOWED`; does not forward `cookie` or query string; always sends `GET`; sets `cache-control: no-store`, `vary: Origin`, and `access-control-allow-origin: https://status.gymtrack.ch` when `origin === "https://status.gymtrack.ch"`.

## Part C: Middleware and request security

Enforced by `apps/web/src/middleware.ts` (matcher: `/((?!_next/static|_next/image|favicon.ico).*)`) and `apps/web/src/request-security.ts`:

- **Configuration guard**: `readWebSecurityConfig()` validates `APP_BASE_URL` (required and must be `https://` in production when `APP_ENV` is neither `"local"` nor `"private-lan"`, defaulting to `http://localhost:3000` otherwise), `APP_ALLOWED_HOSTS`, `APP_ALLOWED_ORIGINS`, `APP_REDIRECT_HOSTS`, and `HSTS_ENABLED`. If config fails to parse, `middleware` returns `503 WEB_SECURITY_MISCONFIGURED`.
- **Canonical host redirect**: `canonicalRedirectTarget()` checks `host` against `redirectHosts` (by default the registrable domain and `www.` variant of `canonicalHostname`, minus any host in `allowedHosts`, unless overridden by `APP_REDIRECT_HOSTS`) and issues a `308` permanent redirect to `${canonicalOrigin}${pathname}${search}` with security headers.
- **Host guard**: `evaluateRequestSecurity()` rejects requests whose `host` header is missing, malformed, or not in `allowedHosts` (canonical hostname, `APP_ALLOWED_HOSTS`, plus `127.0.0.1`/`localhost` when not production) with `421 UNTRUSTED_HOST`.
- **CORS preflight block on `/api`**: For `/api` and `/api/*`, `OPTIONS` requests are rejected with `403 CORS_NOT_ALLOWED`.
- **CSRF origin check on `/api`**: For state-changing methods (`DELETE`, `PATCH`, `POST`, `PUT`) on `/api` and `/api/*`, `evaluateRequestSecurity()` requires a valid `origin` header present in `allowedOrigins` and `sec-fetch-site` not equal to `"cross-site"`, otherwise returning `403 CSRF_ORIGIN_MISMATCH`.
- **Security response headers**: `applySecurityHeaders()` sets the following headers on redirects, rejections, and passed responses:
  - `Content-Security-Policy: base-uri 'self'; form-action 'self'; frame-ancestors 'none'`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `Strict-Transport-Security: max-age=31536000; includeSubDomains` (only when `HSTS_ENABLED=true`, `canonicalOrigin` starts with `https://`, and request hostname matches `canonicalHostname`).
