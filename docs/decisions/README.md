# Architecture Decision Records

This directory stores short architecture decision records for important project tradeoffs.

Use an ADR when a decision changes the long-term direction of the app, such as stack selection, database policy, authentication, API shape, deployment, or major module boundaries.

## Format

Each ADR should use this structure:

```markdown
# ADR 0000 - Short Title

## Status

Proposed | Accepted | Superseded

## Context

What problem or tradeoff forced the decision?

## Decision

What did we choose?

## Consequences

What becomes easier, harder, or constrained because of this?
```

Use sequential numbering and keep each record focused on one decision.
