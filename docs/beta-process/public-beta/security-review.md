# Focused Public Beta Security Review

Date: 2026-08-05. Scope: repository implementation review; not a penetration test or deployed-infrastructure attestation.

| Threat | Implemented boundary / evidence | Remaining launch evidence |
| --- | --- | --- |
| IDOR and user isolation | Existing repositories scope workouts, templates, sets, analytics and exports by authenticated user; database integration tests exercise cross-user workout denial. Export queries independently constrain every ownership join. | Run multi-account API/browser matrix against production build, including guessed UUIDs and shared exercises. |
| Administrator authorization | `users.role` is constrained to `USER/ADMIN`; every beta/campaign/support mutation authenticates then checks `ADMIN`; web page guard is secondary only. Bootstrap is an explicit audited operator CLI, never email inference at runtime. | Verify first promotion record, MFA/operator access and direct-API `USER` denial in staging. |
| Invitation reuse/expiry/email | Only hashed tokens persist. Signup locks the invitation row, requires `INVITED`, unused, unexpired and exact case-insensitive email, then consumes it in the account/session transaction. Integration test covers wrong email and reuse. | Test expired token and resend against staging email; inspect logs/provider events for raw token leakage. |
| Cap races and kill switches | Approval locks the settings singleton before counting active/deletion-pending/suspended accounts and unexpired invitations; a concurrent integration test proves only one of two approvals can take the final seat. Environment and three runtime controls are independent. | Rehearse production pause and direct-API bypass attempts before removing the outer private gate. |
| CSRF/CORS/host attacks | Next ingress rejects untrusted hosts, OPTIONS and state-changing BFF requests without an allowlisted Origin or with cross-site fetch metadata. API has no CORS credentials opt-in; session cookie is SameSite=Lax. Existing tests cover the ingress policy. | Black-box canonical/LAN/Cloudflare host and Origin behavior after final edge configuration. |
| Brute force/enumeration | Login lockout plus route limits; waitlist has a generic accepted response for duplicate/account/blocked/paused state; forgot-password is generic. Signed BFF attribution prevents all public clients sharing or spoofing the internal BFF identity when correctly configured. | Distributed/parallel timing and response comparison; verify matching BFF secrets and edge header overwrite. No CAPTCHA is planned, so monitor abuse. |
| Stored feedback/XSS | Campaigns store bounded plain text and validated HTTPS links only; response union and 1,000-character cap are server validated; React renders text rather than arbitrary HTML. Security headers deny framing and constrain forms/base. | Browser test hostile title/body/choice/free-text payloads; reconsider a fuller CSP after measuring Next production requirements. |
| Deletion authorization | Scheduling/export require current Argon2 password; scheduling immediately revokes sessions; cancellation requires a hashed, single-use, unexpired token or explicit audited admin action. Finalization rechecks state/deadline under a row lock and is idempotent. | Test stolen/expired/reused cancellation tokens, parallel cleanup/cancellation and production email failure. |
| Token/log/metric leakage | API logger redacts bodies, cookies, authorization, email/token/secret fields; request logs contain normalized routes and no query/body; BFF normalizes IDs and excludes query strings; metric labels are bounded. Telegram contains reference/time only. | Run deployed secret audit, inspect Resend/Cloudflare/Telegram access logs, and confirm 30-day retention. |
| Client IP trust / BFF bypass | Browser forwarding headers are not trusted by Fastify. Next selects the platform edge IP, overwrites private attribution headers and HMAC-signs it; API accepts only a timing-safe valid signature. When the production secret is configured, every non-health/metrics API request without that proof is rejected. Unit tests cover forged/invalid/unsigned input. | Review the final edge’s canonical client-IP header, match both secrets, and black-box the public API hostname before removing the outer private gate. |

## Review conclusion

No known repository-level issue in this focused review justifies bypassing a launch gate. The system remains **not approved for public traffic** until the remaining black-box, penetration-style authorization, provider, infrastructure, capacity, real-device and restore tests in `launch-gates.md` are evidenced. Any failure involving isolation, deletion, recovery email, backup/ledger replay or cap enforcement is a stop condition.
