# Focused Public Beta Security Review

Date: 2026-08-05; Goal 1 repository controls reviewed 2026-08-06; repository-level evidence extended 2026-08-20; deployed SQC-1 review closed 2026-08-27. Scope: repository implementation plus the linked deployed-infrastructure and black-box attestations; not an independent penetration test.

| Threat | Implemented boundary / evidence | Closure evidence |
| --- | --- | --- |
| IDOR and user isolation | Existing repositories scope workouts, templates, sets, analytics and exports by authenticated user; database integration tests exercise cross-user workout denial. Mutation IDs are unique only under an owned workout/session-exercise parent, so the same UUID cannot reveal or conflict with another user's row. Export queries independently constrain every ownership join. | **API matrix covered 2026-08-20** by `workout-flow.integration-test.ts`: a foreign workout and a guessed UUID answer identically (404), writes aimed at another account's workout, session exercise and set are refused, the same client mutation id from two accounts produces independent rows, and another member may log a shared exercise but not edit its definition. **Browser matrix run against deployed production 2026-08-21** with two real accounts: an ordinary member reading another member's workout and reading a guessed UUID both returned 404, so the status code cannot confirm a workout exists. Critically, the promoted ADMIN account reading an ordinary member's workout also returned 404 — administrator role grants administrative routes, not other members' training data, so promotion does not widen data access. The cross-account write probe completed on 2026-08-26: an ordinary member posting an exercise into another member's workout received 404, so the workout is invisible rather than merely forbidden. Row closed. |
| Administrator authorization | `users.role` is constrained to `USER/ADMIN`; every beta/campaign/support/containment mutation authenticates then checks `ADMIN`; the web guard is secondary only. Canonical user status/session endpoints lock ordinary-user targets, transact the audit event, reject administrator/self targets and preserve the deletion-cancellation boundary. Bootstrap remains an explicit audited operator CLI, never email inference at runtime. | **Closed.** `public-beta-flow.integration-test.ts` proves direct-API `USER` denial for the user list, audit events, beta settings, status change and session revoke, with the target unchanged. `admin.service.test.ts` and `admin.routes.test.ts` cover bounded audit-event pagination and authorization. PROD-2 records the first controlled promotion and audit row. Administrator/self containment tests preserve the deletion-cancellation boundary. |
| Invitation reuse/expiry/email | Only hashed tokens persist. Signup locks the invitation row, requires `INVITED`, unused, unexpired and exact case-insensitive email, then consumes it in the account/session transaction. Approval/reissue reports synchronous provider acceptance, audits `SENT`/`FAILED`, rotates the unused link and preserves `INVITED` on delivery failure for explicit resend. | **Closed.** `public-beta-flow.integration-test.ts` proves expiry, reuse, supersede-after-reissue and wrong-address rejection. PROD-7 and the SQC-9 outage rehearsal prove both provider `SENT` and `FAILED` behavior. A raw link necessarily exists in the contracted provider's message body so the recipient can use it; opening a real member's provider event would expose that content without proving a stronger boundary. The relevant control is therefore processor access and retention, not absence from the processor: [Resend documents 30-day email/log retention](https://resend.com/docs/dashboard/webhooks/how-to-store-webhooks-data), while application storage and telemetry retain only token hashes and bounded metadata. |
| Cap races and kill switches | Approval locks the settings singleton before counting active/deletion-pending/suspended accounts and unexpired invitations; a concurrent integration test proves only one of two approvals can take the final seat. Environment and three runtime controls are independent. | **Closed.** The final-seat race passes in PostgreSQL integration. PROD-1, PROD-3, PROD-4, PROD-5 and SQC-9 record the production registration pause, runtime controls, tokenless signup refusal, direct-API/BFF refusal and campaign controls with each changed control restored. |
| CSRF/CORS/host attacks | Next ingress rejects untrusted hosts, OPTIONS and state-changing BFF requests without an allowlisted Origin or with cross-site fetch metadata. API has no CORS credentials opt-in; session cookie is SameSite=Lax. Existing tests cover the ingress policy. | **Origin behaviour black-boxed 2026-08-21** against the real edge once Access no longer answered first: a state-changing request with no `Origin` and one with a hostile `Origin` both return `403 CSRF_ORIGIN_MISMATCH`, and a hostile CORS preflight returns 403. **Host behaviour black-boxed 2026-08-23** from outside: requests to the public origin carrying `Host: evil.example.com`, `Host: localhost` and `Host: 192.168.1.57` were each rejected with 403 while the canonical host returned 200. Rejection occurs at the Cloudflare edge rather than reaching the origin's own 421, so a request claiming another host never reaches the application. Row closed. |
| Brute force/enumeration | Login lockout plus route limits; waitlist has a generic accepted response for duplicate/account/blocked/paused state; forgot-password is generic. Signed BFF attribution prevents all public clients sharing or spoofing the internal BFF identity when correctly configured. | **Response comparison covered 2026-08-20** for password reset: a known and an unknown address return identical status and body. **Login timing measured on deployed production 2026-08-26**, after the enumeration fix shipped in `9bbca92`. Four failed logins against a real username interleaved with four against nonsense usernames, from an external network: known 0.796/0.486/0.402/0.504 s (mean 0.547), unknown 0.365/1.025/0.351/0.394 s (mean 0.534). The distributions overlap completely, the means differ by under 3%, and the slowest single sample falls on the unknown side. An earlier one-sided run on 2026-08-23 appeared to show a ~400 ms gap; a repeat showed that was network jitter rather than signal, so it is superseded by this interleaved measurement. The evidence that carries the row is structural — both branches now perform an Argon2id verify, so the code path is identical — with the measurement confirming no gross timing signal survives over the public network. Matching BFF secrets and edge header overwrite are evidenced under PROD-5: the server-side check confirmed both services share a 32+ character secret, and a browser request carrying forged `X-Gym-Client-IP` and `X-Gym-Client-Signature` returned 200 with the forgery stripped by the proxy's `header_up -` directives before reaching the BFF. Row closed. No CAPTCHA is planned, so monitor abuse. |
| Stored feedback/XSS and CSV formulas | Campaigns store bounded plain text and validated HTTPS links only; response union and 1,000-character cap are server validated; React renders text rather than arbitrary HTML. Security headers deny framing and constrain forms/base. CSV export and the sample use Papa Parse formula escaping so user-authored cells open as text in spreadsheet software. | Spreadsheet cell escaping is covered by `workout-csv.test.ts`, which asserts an exported `=SUM(A1:A2)` is written as `'=SUM(A1:A2)`. Hostile payloads were rendered in a browser on 2026-08-26 against deployed production: a campaign carrying `<script>` and `onerror` payloads in its title and body displayed as literal text to a member with no execution and no console errors, and a member's free-text response carrying the same payloads displayed as literal text to the administrator. Both directions hold. **No test work remains on this row.** A fuller CSP is deliberately deferred post-beta: it is a design decision requiring measurement of Next.js production requirements, not evidence to be gathered, and the current headers already deny framing and constrain forms and base URIs. Recorded here so it is not mistaken for outstanding test work. |
| Workout write races/replays | Exercise/set creates require a logical-action UUID and use parent-scoped partial unique indexes. Ownership, parent locking, order shifts/compaction and insertion are transactional; equivalent replays return the existing row and mismatched reuse returns `409`. Reorder/update remain explicit last-write-wins with authoritative refetch. | **Closed for the Founding Beta boundary.** PostgreSQL integration proves idempotent replay, mismatched-reuse conflict, ordered-write serialization and cross-user repeated-ID isolation. SQC-2 exercised concurrent end-to-end writes on PostgreSQL 17 with zero failures. An exhaustive add/reorder/delete interleaving model is useful post-beta hardening, not a separate launch assertion once these ownership, transaction, replay and capacity properties are proven. |
| Browser draft privacy | Active-set drafts are versioned, user/workout/exercise-scoped local-storage envelopes with an exact 24-hour maximum after last edit. Malformed, legacy and expired values are deleted; save/discard/workout/account/device-clear flows remove them. | **Closed 2026-08-21** against deployed production. Signing out removes the active-set draft entirely rather than merely scoping it: after a sign-out and sign-in as a different account on the same browser, no `gym-progress:set-draft:` key remained in local storage and nothing from the previous account surfaced. A draft cannot be carried through a logout at all, so a shared device cannot leak one. |
| Accessibility containment | Browser zoom restrictions are removed. Shared modal behavior provides initial focus, a keyboard trap, Escape close, inert background, scroll lock and focus restoration; informational popovers remain non-modal. Automated keyboard and axe coverage exercises representative public, auth and authenticated surfaces. | **Closed at the approved Founding Beta scope.** SQC-6, SQC-7 and SQC-8 record automated axe/interaction coverage, physical-device touch/keyboard behavior, contrast, keyboard/focus and reduced-motion passes. The controller deliberately descoped screen-reader support for this founding cohort; it remains required before broadening that audience, not an unfinished SQC-1 test. |
| Deletion authorization and delivery | Scheduling/export require current Argon2 password; scheduling immediately revokes sessions; cancellation requires a hashed, single-use, unexpired token or explicit audited admin action. Required scheduling-email failure compensates to `ACTIVE` and invalidates the token; cancellation survives informational-email failure. Finalization rechecks state/deadline under a row lock and continues across per-account/email failures. | **Closed.** Integration coverage proves reused/tampered cancellation rejection, grace-period lock, admin and link cancellation, idempotent finalization, shared-exercise cleanup, erasure-ledger replay and both real-provider failure branches. Commit `c41d32c` adds the missing parallel cancellation-versus-finalization race: exactly one operation wins under row locking, and the resulting account/tombstone state remains consistent. Exact-SHA CI run `33066859946` passes all three jobs including PostgreSQL integration. |
| Lifecycle liveness | A startup-and-hourly, API-owned single-flight scheduler isolates auth, invitation, deletion, retention and notification failures. Bounded metrics and alert rules cover two-hour staleness, four-hour critical failure/backlog and repeated delivery failures. | **Closed 2026-08-27.** Production runs the exact single-API topology at release `9bbca92`. All 31 Prometheus rules pass `promtool` validation and are healthy after live reload, including the four lifecycle/email rules. A temporary no-impact lifecycle rule was observed pending then firing on the deployed alert path, removed, and confirmed absent. Current lifecycle metrics show a successful hourly run, bounded duration and zero due deletions; startup catch-up and per-task isolation remain covered by scheduler tests. A literal four-hour outage would only repeat the already-proven threshold evaluation while creating avoidable production degradation, so it is not required. |
| Token/log/metric leakage | API logger redacts bodies, cookies, authorization, email/token/secret fields; request logs contain normalized routes and no query/body; BFF normalizes IDs and excludes query strings. Transactional-email telemetry is bounded to kind/outcome/provider status/message ID/duration and excludes recipient/body/link/token. Telegram contains reference/time only. | **Closed 2026-08-27.** Source and full-history secret scans found no credential pattern; only example environment files are tracked and real environment files are ignored. The deployed proxy sentinel test and PROD-5 prove sensitive inbound headers are stripped. Production metrics expose only bounded route/status/kind/outcome/release labels—no email, user, recipient, token or request ID—and Telegram beta notification variables remain unset under PROD-8. [Cloudflare documents](https://developers.cloudflare.com/cloudflare-one/insights/logs/) 24-hour Free-plan Access/HTTP log retention and 18-month administrative logs; [Resend documents](https://resend.com/security/gdpr) 30-day email/log retention and seven-day backup retention. These processor-held fields and periods are already recorded in the processor inventory and [DPA boundary](https://resend.com/legal/dpa). |
| Client IP trust / BFF bypass | Browser forwarding headers are not trusted by Fastify. Next selects the platform edge IP, overwrites private attribution headers and HMAC-signs it; API accepts only a timing-safe valid signature. When the production secret is configured, every non-health/metrics API request without that proof is rejected. Unit tests cover forged/invalid/unsigned input. | **Closed under PROD-5.** Production uses Cloudflare's canonical client-address header, both services share the protected secret, Caddy strips caller-supplied attribution headers, an unsigned direct API request is refused, and the public origin does not expose the Fastify surface. A black-box forged-header probe completed normally only after the forgery was stripped. |

## Review conclusion

SQC-1 is complete for the Founding Beta. Repository evidence is mapped in [goal-1-remediation-report.md](goal-1-remediation-report.md), and the table above connects it to the deployed black-box, infrastructure, provider and lifecycle evidence. This is approval of the defined security-quality gate, not a claim of independent penetration testing or authorization to begin Goal 6. Any failure involving isolation, deletion, unexplained workout writes, recovery email, cleanup, backup/ledger replay or cap enforcement remains a rollout stop condition.
